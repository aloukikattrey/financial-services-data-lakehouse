# Oracle Source System Setup

## Purpose

This document records the local Oracle source-system setup for the Financial Services Data Lakehouse project.

The Oracle database is a synthetic operational source that models the type of financial data domain used by enterprise reporting systems. It is independent of any employer/client environment and contains no proprietary data.

## Architecture

```text
Windows PC
   |
Docker Desktop
   |
Oracle Database Free Lite
   |
FREEPDB1
   |
FINANCE_APP
   |
+-------------------+
| CLIENT            |
| ACCOUNT           |
| PORTFOLIO         |
| SECURITY          |
| HOLDINGS          |
| TRN_TRANSACTIONS  |
+-------------------+
   |
   | JDBC / network connection
   v
Azure Databricks
```

## Prerequisites

- Windows machine
- Docker Desktop installed and running
- Existing Oracle Database Free Lite image:
  `container-registry.oracle.com/database/free:latest-lite`

## Container Setup

### Confirm Oracle image

```powershell
docker images
```

The project uses the existing Oracle image:

```text
container-registry.oracle.com/database/free:latest-lite
```

### Create persistent Docker volume

```powershell
docker volume create oracle-finance-data
```

### Create Oracle container

Use a strong local password and do not commit it to GitHub.

```powershell
docker run -d `
  --name oracle-finance-db `
  --hostname oracle-finance-db `
  -p 1521:1521 `
  -e ORACLE_PWD="YOUR_NEW_PASSWORD" `
  -v oracle-finance-data:/opt/oracle/oradata `
  container-registry.oracle.com/database/free:latest-lite
```

### Wait for database initialization

```powershell
docker logs -f oracle-finance-db
```

Wait for:

```text
DATABASE IS READY TO USE!
```

### Verify container

```powershell
docker ps
```

The container should expose:

```text
0.0.0.0:1521->1521/tcp
```

## Oracle Listener Verification

```powershell
docker exec oracle-finance-db lsnrctl status
```

The listener should be available on port `1521`, and the `FREE` and `freepdb1` services should show `READY`.

## Initial Oracle Connection

The working connection pattern used for the clean container is:

```powershell
docker exec -it oracle-finance-db sqlplus system@//localhost:1521/FREE
```

Enter the Oracle password when prompted.

Verify the connection:

```sql

```

Expected:

```text
SYSTEM
```

## FINANCE_DATA Tablespace

The Oracle Free Lite instance did not contain a `USERS` tablespace, so a dedicated application tablespace was created.

```sql
CREATE TABLESPACE FINANCE_DATA
DATAFILE '/opt/oracle/oradata/FREE/FREEPDB1/finance_data01.dbf'
SIZE 100M
AUTOEXTEND ON
NEXT 10M
MAXSIZE 1G;
```

## FINANCE_APP User

Create the dedicated application schema/user:

```sql
CREATE USER FINANCE_APP IDENTIFIED BY "YOUR_NEW_PASSWORD";
```

Assign the application tablespace:

```sql
ALTER USER FINANCE_APP DEFAULT TABLESPACE FINANCE_DATA;
```

Grant quota:

```sql
ALTER USER FINANCE_APP QUOTA UNLIMITED ON FINANCE_DATA;
```

Grant required development privileges:

```sql
GRANT CREATE SESSION, RESOURCE TO FINANCE_APP;
```

Verify:

```sql
SELECT USERNAME, ACCOUNT_STATUS, DEFAULT_TABLESPACE
FROM DBA_USERS
WHERE USERNAME = 'FINANCE_APP';
```

Expected state:

```text
FINANCE_APP    OPEN    FINANCE_DATA
```

## Source Data Model

The synthetic operational source models a financial transaction-and-holdings domain:

```text
CLIENT
  |
ACCOUNT
  |
PORTFOLIO
  |\
  | \
  |  HOLDINGS
  |       \
  |        SECURITY
  |
  +-- TRN_TRANSACTIONS -- SECURITY
```

### Core tables

- `CLIENT` — institutional/client entities
- `ACCOUNT` — client-owned accounts
- `PORTFOLIO` — investment portfolios associated with accounts
- `SECURITY` — security/instrument master
- `HOLDINGS` — portfolio positions by as-of date
- `TRN_TRANSACTIONS` — trading and other portfolio transactions

## Table Creation DDL

### CLIENT

```sql
CREATE TABLE CLIENT (CLIENT_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, CLIENT_CODE VARCHAR2(20) NOT NULL, CLIENT_NAME VARCHAR2(200) NOT NULL, CLIENT_TYPE VARCHAR2(50), BASE_CURRENCY CHAR(3) DEFAULT 'USD', COUNTRY_CODE CHAR(2), STATUS VARCHAR2(20) DEFAULT 'ACTIVE', CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_CLIENT PRIMARY KEY (CLIENT_ID), CONSTRAINT UK_CLIENT_CODE UNIQUE (CLIENT_CODE));
```

### ACCOUNT

```sql
CREATE TABLE ACCOUNT (ACCOUNT_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, ACCOUNT_NUMBER VARCHAR2(30) NOT NULL, CLIENT_ID NUMBER NOT NULL, ACCOUNT_TYPE VARCHAR2(50), BASE_CURRENCY CHAR(3) DEFAULT 'USD', STATUS VARCHAR2(20) DEFAULT 'ACTIVE', OPEN_DATE DATE, CLOSE_DATE DATE, CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_ACCOUNT PRIMARY KEY (ACCOUNT_ID), CONSTRAINT UK_ACCOUNT_NUMBER UNIQUE (ACCOUNT_NUMBER), CONSTRAINT FK_ACCOUNT_CLIENT FOREIGN KEY (CLIENT_ID) REFERENCES CLIENT(CLIENT_ID));
```

### PORTFOLIO

```sql
CREATE TABLE PORTFOLIO (PORTFOLIO_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, PORTFOLIO_CODE VARCHAR2(30) NOT NULL, ACCOUNT_ID NUMBER NOT NULL, PORTFOLIO_NAME VARCHAR2(200), PORTFOLIO_TYPE VARCHAR2(50), BASE_CURRENCY CHAR(3) DEFAULT 'USD', STATUS VARCHAR2(20) DEFAULT 'ACTIVE', INCEPTION_DATE DATE, CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_PORTFOLIO PRIMARY KEY (PORTFOLIO_ID), CONSTRAINT UK_PORTFOLIO_CODE UNIQUE (PORTFOLIO_CODE), CONSTRAINT FK_PORTFOLIO_ACCOUNT FOREIGN KEY (ACCOUNT_ID) REFERENCES ACCOUNT(ACCOUNT_ID));
```

### SECURITY

```sql
CREATE TABLE SECURITY (SECURITY_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, SECURITY_CODE VARCHAR2(30) NOT NULL, ISIN VARCHAR2(20), TICKER VARCHAR2(20), SECURITY_NAME VARCHAR2(200) NOT NULL, SECURITY_TYPE VARCHAR2(50), CURRENCY_CODE CHAR(3) DEFAULT 'USD', EXCHANGE_CODE VARCHAR2(20), COUNTRY_CODE CHAR(2), ACTIVE_FLAG CHAR(1) DEFAULT 'Y', CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_SECURITY PRIMARY KEY (SECURITY_ID), CONSTRAINT UK_SECURITY_CODE UNIQUE (SECURITY_CODE), CONSTRAINT UK_SECURITY_ISIN UNIQUE (ISIN));
```

### HOLDINGS

```sql
CREATE TABLE HOLDINGS (HOLDING_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, PORTFOLIO_ID NUMBER NOT NULL, SECURITY_ID NUMBER NOT NULL, AS_OF_DATE DATE NOT NULL, QUANTITY NUMBER(20,6) DEFAULT 0, UNIT_PRICE NUMBER(20,8), MARKET_VALUE NUMBER(24,8), COST_BASIS NUMBER(24,8), CURRENCY_CODE CHAR(3) DEFAULT 'USD', CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_HOLDINGS PRIMARY KEY (HOLDING_ID), CONSTRAINT FK_HOLDINGS_PORTFOLIO FOREIGN KEY (PORTFOLIO_ID) REFERENCES PORTFOLIO(PORTFOLIO_ID), CONSTRAINT FK_HOLDINGS_SECURITY FOREIGN KEY (SECURITY_ID) REFERENCES SECURITY(SECURITY_ID), CONSTRAINT UK_HOLDINGS_POSITION UNIQUE (PORTFOLIO_ID, SECURITY_ID, AS_OF_DATE));
```

### TRN_TRANSACTIONS

```sql
CREATE TABLE TRN_TRANSACTIONS (TRANSACTION_ID NUMBER GENERATED BY DEFAULT AS IDENTITY, PORTFOLIO_ID NUMBER NOT NULL, SECURITY_ID NUMBER NOT NULL, TRANSACTION_DATE TIMESTAMP NOT NULL, SETTLEMENT_DATE DATE, TRANSACTION_TYPE VARCHAR2(30) NOT NULL, BUY_SELL_FLAG CHAR(1), QUANTITY NUMBER(20,6), PRICE NUMBER(20,8), GROSS_AMOUNT NUMBER(24,8), FEES NUMBER(24,8) DEFAULT 0, NET_AMOUNT NUMBER(24,8), CURRENCY_CODE CHAR(3) DEFAULT 'USD', TRADE_STATUS VARCHAR2(30) DEFAULT 'COMPLETED', SOURCE_REFERENCE VARCHAR2(50), CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT PK_TRN_TRANSACTIONS PRIMARY KEY (TRANSACTION_ID), CONSTRAINT FK_TRN_PORTFOLIO FOREIGN KEY (PORTFOLIO_ID) REFERENCES PORTFOLIO(PORTFOLIO_ID), CONSTRAINT FK_TRN_SECURITY FOREIGN KEY (SECURITY_ID) REFERENCES SECURITY(SECURITY_ID), CONSTRAINT UK_TRN_SOURCE_REFERENCE UNIQUE (SOURCE_REFERENCE));
```

## Synthetic Data Generation

### Clients

Ten synthetic clients were created with fictional names, codes, currencies, types, and country codes.

### Accounts

Twenty synthetic accounts were created, mapped to the ten clients.

### Portfolios

Thirty synthetic portfolios were created across the accounts.

### Securities

One hundred synthetic securities were created across equities, ETFs, government bonds, corporate bonds, funds, and other instrument categories.

### Holdings

Synthetic holdings were generated for multiple as-of dates, including:

- 2026-06-30
- 2026-07-31
- 2026-08-21

The holdings model uses a uniqueness constraint on portfolio, security, and as-of date.

### Transactions

5,000 synthetic transactions were generated across portfolios and securities. Transaction types include buy, sell, dividend, and transfer activity, with a mix of completed, pending, and failed statuses.

## Validation and Financial Consistency

After transaction generation, the project validates:

```sql
SELECT COUNT(*)
FROM TRN_TRANSACTIONS
WHERE GROSS_AMOUNT <> ROUND(QUANTITY * PRICE, 8);
```

Expected result after correction: `0`.

And:

```sql
SELECT COUNT(*)
FROM TRN_TRANSACTIONS
WHERE NET_AMOUNT <> ROUND(GROSS_AMOUNT + NVL(FEES, 0), 8);
```

Expected result: `0`.

## Important Security Rules

- Never commit Oracle passwords or any other credentials.
- Do not commit `.env` files containing secrets.
- Do not use real Wellington/client data.
- Do not copy employer SQL, schemas, identifiers, or business rules into this public repository.
- All source data for this personal project must remain synthetic.
